# Nuvera Form storefront

Static site (`index.html` plus pages generated by `tools/build-pages.py`) and serverless functions in `api/`: `welcome.js` (account welcome email with NUVERA20, Resend contact), `subscribe.js` (newsletter contact) and `order.js` (emails the customer their Zelle payment instructions). Orders are also sent to the owner through Web3Forms. Shared helpers, origin check and rate limits are in `api/_lib.js`.

## 1. GitHub
```bash
cd nuvera-form
git init -b main
git add .
git commit -m "Initial Nuvera Form storefront"
# create an empty repo named nuvera-form on github.com first, then:
git remote add origin https://github.com/YOUR-USER/nuvera-form.git
git push -u origin main
```

## 2. Vercel
1. vercel.com > Add New > Project > import the GitHub repo. Framework preset: Other. No build command.
2. Settings > Environment Variables, add the three values from `.env.example` (Production and Preview).
3. Deploy. Every push to `main` redeploys automatically.

## 3. Domain (nuveraform.com)
1. Vercel > Project > Settings > Domains > add `nuveraform.com` and `www.nuveraform.com`.
2. At your registrar, add the records Vercel shows you. Typically:
   - `A` record, host `@`, value `76.76.21.21`
   - `CNAME`, host `www`, value `cname.vercel-dns.com`
   Use the exact values Vercel displays for your project if they differ.
3. Wait for propagation (minutes to a few hours). Vercel issues the HTTPS certificate automatically.

## 4. Resend (email)
1. resend.com > Domains > add `nuveraform.com`.
2. Add the SPF and DKIM DNS records Resend gives you at your registrar (they are specific to your account), then click Verify.
3. Create an API key (sending access only) and paste it into Vercel as `RESEND_API_KEY`. Redeploy.
4. Test: sign up on the live site with your own email.

## 5. Web3Forms
The access key in `index.html` is a public key by design. In the Web3Forms dashboard, add `nuveraform.com` as an allowed domain and set the notification email for leads and affiliate applications.

## 6. Before taking payments
Checkout is currently manual (Zelle to (305) 457-3814, confirmed by hand). Before adding card payments, have the Privacy and Terms text reviewed, and confirm every claim on the site is supportable. The `api/` rate limits are per server instance; add Vercel Firewall rate limiting or a CAPTCHA if abuse appears.

## Live inventory, orders and admin
- Stock lives in Upstash Redis (Vercel → Storage → Marketplace → Upstash Redis → connect to this project; it adds `KV_REST_API_URL` and `KV_REST_API_TOKEN`).
- `api/order.js` prices orders from `api/_catalog.js`, reserves stock atomically, saves the order and emails the owner and customer.
- Bundles take their stock from their parts (`parts` in `_catalog.js`).
- `/admin` (set `ADMIN_TOKEN` in Vercel): set stock after a restock, mark orders paid, cancel an order to put its items back.
- Changing a price or product: edit BOTH `index.html` (P array) and `api/_catalog.js`, then run `node tools/check-catalog.mjs`.
- Tests: `node tools/test-api.mjs` (fake Redis, mocked Resend).
- If Redis is not connected the site still works with the built-in stock numbers (no live tracking) and orders arrive by email.

## Reviews
Submissions arrive by email (Web3Forms). After matching the order number, add the review to `data/reviews.json` with `"approved": true` (and `"verified": true`), then run `python3 tools/build-pages.py`.
Fields: name, date, rating (1-5), aspect, text, approved, verified.

## Spam protection (Turnstile)
Create a Turnstile widget in Cloudflare, put the site key in `assets/site-config.js` (`TS_KEY`) and the secret in `TURNSTILE_SECRET` in Vercel. Until both are set the forms work without it. Set both together.
